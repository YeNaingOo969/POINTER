# YangonGo – Claude Code Handoff Brief

ဒီဖိုင်ကို Claude Code ထဲမှာ ပထမဆုံး ဖတ်ခိုင်းပါ။ (ဥပမာ project folder ထဲ `CLAUDE.md` အဖြစ် ထားပါ၊ ဒါမှမဟုတ် ပထမ message မှာ "ဒီဖိုင်ကို အစအဆုံးဖတ်ပြီး ညွှန်ကြားချက်အတိုင်း လုပ်ပါ" လို့ ပြောပါ။)

---

## ၁။ မင်းရဲ့ အခန်းကဏ္ဍ (Claude Code အတွက် ညွှန်ကြားချက်)

မင်းက ငါ့ရဲ့ **ဆွေးနွေးဖော် (discussion partner)** နဲ့ **developer** ပါ။ ငါက ကျောင်း group project တစ်ခုရဲ့ **Project Leader** ဖြစ်တယ်။ ဒီ project ကို တခြား Claude chat မှာ စဉ်းစားဆွေးနွေးခဲ့ပြီးပြီ၊ အခု ဆက်ပြီး ဆွေးနွေးမယ်။ အောက်က အချက်တွေ အားလုံး အဲဒီ chat ကနေ ယူလာတာပါ။

**အလုပ်လုပ်ပုံ စည်းကမ်းများ**

1. **Burmese နဲ့ ပြန်ဖြေပါ။** Technical terms၊ code၊ command၊ file path တွေကိုတော့ English အတိုင်း ထားပါ။
2. **အခု code မရေးသေးပါနဲ့။** ဦးစွာ ဆွေးနွေးပါ၊ ငါနဲ့ အတည်ပြုပြီးမှ code ရေးပါ။
3. **ဆွေးနွေးမထားတာကို ဆုံးဖြတ်ပြီးသားလို မရေးပါနဲ့။** အရင် chat မှာ technology တွေကို မဆွေးနွေးရသေးဘဲ ဆုံးဖြတ်ပြီးသားလို ရေးမိလို့ ငါ ပြင်ခိုင်းခဲ့ရတယ်။ ဒီတစ်ခါ အဲဒီလို မဖြစ်စေနဲ့။ အောက်မှာ **"အတည်ပြုပြီး"** နဲ့ **"မဆုံးဖြတ်ရသေး"** ကို ခွဲထားတယ်၊ အဲဒီအတိုင်း လိုက်နာပါ။
4. **မေးခွန်းကို တစ်ခါမှာ တစ်ခု၊ အများဆုံး နှစ်ခုပဲ မေးပါ။** မေးခွန်းအများကြီး တစ်ပြိုင်နက် မပစ်ပါနဲ့။
5. **အကြံပြုတဲ့အခါ ရွေးစရာ ၂-၃ ခုနဲ့ မင်းရဲ့ အကြံ၊ အကြောင်းရင်းကို ပြောပါ။** ငါ မရွေးခင် ဆုံးဖြတ်ပြီးသားလို မရေးပါနဲ့။
6. **ငါ့အကြံက မကောင်းရင် ဝေဖန်ပြီး ပြောပါ။** သဘောတူအောင် လိုက်မပြောပါနဲ့။ ဒါပေမယ့် ယဉ်ကျေးစွာ၊ အကြောင်းရင်းနဲ့ ပြောပါ။
7. **ဆုံးဖြတ်ချက်အသစ်ရတိုင်း** ဒီဖိုင်ရဲ့ **အပိုင်း ၃ (အတည်ပြုပြီး)** ထဲကို ပြောင်းထည့်ဖို့ အကြံပြုပါ၊ ငါ ခွင့်ပြုမှ ပြင်ပါ။ ဒီလိုနဲ့ ဒီဖိုင်က project ရဲ့ နောက်ဆုံးအခြေအနေ ဖြစ်နေစေမယ်။
8. **Tools အကြောင်း:** ငါ့ **global folder** မှာ set up လုပ်ထားပြီးသား tools တွေကို သုံးလို့ရတယ်။ လိုအပ်တဲ့ tools တွေကိုလည်း လိုသလို set up လုပ်ပြီး သုံးလို့ရတယ်။ ဒါပေမယ့် အရင်ဆုံး ဘာ tools တွေ ရှိပြီးသားလဲ စစ်ကြည့်ပြီး ငါ့ကို ပြောပြပါ၊ ပြီးမှ ဘာထပ်လိုလဲ အကြံပြုပါ။
9. ငါက ဒီ project မှာ အဖွဲ့ကို ဦးဆောင်ရတဲ့ leader ဖြစ်တယ်၊ အဖွဲ့ဝင်တွေကို ရှင်းပြဖို့လည်း လိုလိမ့်မယ်။ ဒါကြောင့် ရှင်းပြတဲ့အခါ ရိုးရှင်းပြီး နားလည်လွယ်အောင် ပြောပါ။

---

## ၁.၁ အဖွဲ့ဖွဲ့စည်းပုံနဲ့ မင်းရဲ့ code ရေးတဲ့ နယ်ပယ် (အတည်ပြုပြီး၊ အရေးကြီးဆုံး)

**အဖွဲ့ဖွဲ့စည်းပုံ**
- **Backend**: ၂ ယောက်
- **Frontend**: ငါ တစ်ယောက်တည်း တာဝန်ယူတယ်

**အလုပ်ဆက်ဆံပုံ**
- ငါက frontend ကို ရေးပြီး user flow (ဘယ် page က ဘယ်ကိုသွားလဲ၊ ဘာနှိပ်ရင် ဘာဖြစ်လဲ) ကို ပြမယ်။
- Backend ၂ ယောက်က ငါ့ frontend ကို ကြည့်ပြီး **backend ကို သူတို့ ပြန်ရေးမယ်**။

**ဒါကြောင့် မင်းက ရေးရမှာ**: **Frontend UI/UX ကို "အသေ" (static) အနေနဲ့ပဲ ရေးပါ။**

- **Backend code၊ database၊ server logic၊ API implementation မရေးပါနဲ့။**
- Data တွေ (နေရာစာရင်း၊ review၊ user စတာ) ကို **hardcode / mock data** နဲ့ ပြပါ။ Mock data ကို **တစ်နေရာတည်း (သီးသန့် data file)** မှာ စုထားပါ၊ ဒါမှ backend တွေက ဘာ data လိုတယ်ဆိုတာ မြင်လွယ်မယ်။
- Login၊ form submit၊ review တင်တာ စတာတွေကို **UI နဲ့ flow အနေနဲ့ပဲ** ပြပါ။ တကယ် မသိမ်းဘူး (ဟန်ပြ simulate လုပ်လို့ရတယ်)။
- Frontend ကို backend နဲ့ ပြန်ချိတ်ရလွယ်အောင် **ရှင်းရှင်းလင်းလင်း၊ အပိုင်းလိုက် ခွဲပြီး** ရေးပါ။ Backend က PHP ဖြစ်ချင်လည်း ဖြစ်နိုင်လို့ (အောက်မှာ ကြည့်ပါ) page တွေကို backend က ပြန်ယူသုံးရလွယ်တဲ့ ပုံစံကို ဦးစားပေးပါ။ Frontend framework ဘာရွေးမလဲ ဆိုတာ ငါနဲ့ ဆွေးနွေးပါ။
- **Backend ဘာသုံးမလဲ (PHP / JavaScript)** က backend ၂ ယောက်နဲ့ ငါ ညှိပြီး ဆုံးဖြတ်မယ်။ မင်း မရွေးပါနဲ့။

**Backend ၂ ယောက်အတွက် Handoff note**

Frontend နဲ့အတူ handoff note တစ်ခုလည်း ရေးပေးပါ။ အနည်းဆုံး ဒါတွေပါရမယ်။
- Page စာရင်း၊ page တစ်ခုချင်းစီရဲ့ အလုပ်
- Form တစ်ခုချင်းစီထဲက field နာမည်တွေ
- Page တစ်ခုချင်းစီက ဘာ data ပြတယ် (mock data ရဲ့ ပုံစံ)
- User ဘာနှိပ်/ဘာတင်ရင် backend က ဘာလုပ်ရမလဲ
- Role (visitor / user / admin) အလိုက် ဘာမြင်ရ၊ ဘာလုပ်ခွင့်ရလဲ

**ငါ့ GitHub repo ထဲက project တွေလို ရေးပါ**

- ငါ့ GitHub repo ထဲမှာ ငါ ပြီးခဲ့တဲ့ project တွေ ရှိတယ်။ ဒီ project ရဲ့ frontend ကို အဲဒီ project တွေနဲ့ **folder structure၊ file နာမည်ပေးပုံ၊ code style၊ UI/UX ချဉ်းကပ်ပုံ** တူအောင် ရေးပါ။
- ဘယ် repo / ဘယ် project ကို ကြည့်ရမလဲ **ငါ့ကို အရင်မေးပါ**။ Git / `gh` နဲ့ ဝင်ကြည့်လို့ရရင် ကြည့်ပါ၊ မရရင် ငါ folder path ပေးမယ်။
- မသေချာရင် မှန်းမရေးပါနဲ့။

## ၂။ Project အကျဉ်းချုပ်

- **နာမည်**: **YangonGo**
- **အမျိုးအစား**: ကျောင်း group project။ **Cinematic website** တစ်ခု ဖန်တီးရမယ်ဆိုတဲ့ သတ်မှတ်ချက်ပါ။
- **အယူအဆ**: ရန်ကုန်မြို့ထဲမှာ လူတွေ တကယ်သွားလည်ပတ်မယ့် နေရာတွေကို **map ပေါ်မှာ ပြပေးတဲ့ city guide website**။ ကြည့်ရတာ ရုပ်ရှင်လို လှတဲ့ (cinematic) ပုံစံနဲ့ ဖော်ပြမယ်။
- **ရည်ရွယ်ချက်**: ကျောင်း project အဖြစ် အရင်ပြီးစီးအောင် လုပ်မယ်၊ နောက်ပိုင်း လုပ်ငန်းအဖြစ် ဆက်ကြီးထွားနိုင်အောင် စိတ်ထဲထားမယ်။
- **ငါ ချင်တာ**: interactive ဖြစ်ရမယ်၊ user တွေ မှတ်မိရမယ်၊ လက်တွေ့ဘဝမှာ အသုံးဝင်ရမယ်၊ unique ဖြစ်ရမယ်၊ graphical အသားပေးရမယ်။
- **Demo**: ကျောင်းမှာ projector နဲ့ ပြမယ်။

### ဒီ idea ကို ဘယ်လို ရောက်လာတာလဲ (နောက်ခံ)

- ပထမ cinematic website ခေါင်းစဉ် အကြံတွေ ဆွေးနွေးခဲ့တယ် (သမိုင်း၊ sci-fi၊ သဘာဝ၊ mystery စတာတွေ)
- ပြီးတော့ interactive + လက်တွေ့အသုံးဝင်တာတွေ၊ game ပုံစံတွေ ဆွေးနွေးခဲ့တယ်
- နောက်ဆုံး ရန်ကုန်မြို့ကို အခြေခံတဲ့ map-based guide ကို ရွေးတယ်
- **Open-world game မဟုတ်ဘူး၊ game လည်း မဟုတ်ဘူး။** Google Maps လိုမျိုး map ပေါ်မှာ လူတွေ တကယ်သွားမယ့် နေရာတွေကို ပြတာပါ။ (ဒါကို အရင်က ကျွန်တော်/Claude မှားပြီး game ဘက်ကို လွန်သွားခဲ့လို့ ငါ ပြင်ခိုင်းခဲ့တယ်။ ပြန်မမှားပါနဲ့။)

## ၃။ အတည်ပြုပြီး ဆုံးဖြတ်ချက်များ (ငါ ပြောခဲ့ပြီးသား)

### ဘာတွေပါမလဲ

- **ဒေသ**: ရန်ကုန်မြို့
- **နေရာအမျိုးအစား**: နေရာကြည့်စရာ၊ ဆိုင်များ၊ ဟိုတယ်၊ နာမည်ကြီးနေရာများ၊ စားသောက်ဆိုင်များ
- **Map**: map ပေါ်မှာ နေရာတွေကို ပြမယ်၊ နေရာကို track လုပ်ပေးမယ်
- **Category filter**: ပါမယ်။ **ဆေးရုံနဲ့ တခြားဝန်ဆောင်မှုစင်တာတွေ** (ဥပမာ nail spa) ကိုလည်း ထည့်ချင်တယ်။ Category တွေကို **အုပ်စုလိုက်ခွဲမယ်**။ ဘယ် category နဲ့မှ မကိုက်တဲ့ ဆိုင်ပိုင်ရှင်တွေလည်း ထည့်လို့ရအောင် လုပ်မယ်။
- **Review နဲ့ rating**: user တွေ ရေးလို့ရမယ်
- **ဆိုင်ပိုင်ရှင်တွေ promotion post တင်လို့ရမယ်**

### ငါရွေးခဲ့တဲ့ ထူးခြားချက် ၃ ခု (Unique Features)

1. **Mood-based search**: စိတ်ခံစားမှုအလိုက် နေရာရှာတာ
2. **Food Passport check-in**: ရောက်ဖူးတဲ့နေရာတွေကို passport stamp လို check-in လုပ်စုတာ
3. **Live crowd report**: နေရာတစ်ခု လက်ရှိ လူများ/နည်းကို user တွေက report လုပ်ပေးတာ

### User Roles

- **Login မဝင်ထားသူ (Visitor)**: ကြည့်ရုံပဲ ရမယ်
- **Login ဝင်ထားသူတိုင်း** ရိုးရိုး **User** ပဲ (tourist ဖြစ်ဖြစ်၊ local ဖြစ်ဖြစ်)
- **Admin**: User ကလွဲရင် ရှိတဲ့ တစ်ခုတည်းသော တခြား role
- **ဆိုင်ပိုင်ရှင် (Owner)** က သီးသန့် role **မဟုတ်ဘူး**။ User တစ်ယောက်က **"Add your business"** feature နဲ့ Facebook page လို business page ဖွင့်တာပါ။
- **Promotion post**: ပိုင်ရှင်က ကြိုတင်ခွင့်ပြုချက်မလိုဘဲ လွတ်လွတ်လပ်လပ် တင်လို့ရတယ်။ **Report ခံရတဲ့ post ကို Admin က ဖယ်ရှားမယ်** (အရင်တင်ပြီး report ခံရမှ စစ်တဲ့ပုံစံ)။

### Platform နဲ့ ဘာသာစကား

- **Desktop**: projector demo မှာ လှရမယ်
- **Phone / tablet**: user တွေ ဖုန်းနဲ့ ကြည့်မှာမို့ အဆင်ပြေရမယ်
- **Admin**: desktop အဓိကသုံးမယ်၊ ဒါပေမယ့် phone မှာလည်း အဆင်ပြေရမယ်
- **ဘာသာစကား**: UI ကို **English default** ထားပြီး **Burmese သို့ ပြောင်းလို့ရမယ်**
- ဆိုင်ပိုင်ရှင်တွေက မြန်မာလို post တင်ကြမှာမို့ **Burmese စာတွေ မှန်ကန်စွာ ပြနိုင်ရမယ်** (UTF-8)
- Browser translate / **Translate button** ကို bonus အနေနဲ့ နောက်မှ ထည့်မယ်

### ထည့်မယ့်အရာနဲ့ မထည့်မယ့်အရာ

- **Friends location tracking** (Snapchat လိုမျိုး သူငယ်ချင်းတွေရဲ့ location ကြည့်တာ) ကို **အခု မထည့်ဘူး**။ အချိန်မီပြီးမှ ထပ်ထည့်ခိုင်းချင်ရင် ငါ ပြန်ပြောမယ်။ ဒါက backend၊ login၊ friend system၊ real-time၊ privacy ပြဿနာတွေ လိုလို့ ခက်တယ်ဆိုတာ ဆွေးနွေးပြီးသား။
- **Game၊ open-world** မလုပ်ဘူး။

### Technology အတွက် ကန့်သတ်ချက်များ (ငါ ပြောခဲ့တာ)

- **Backend**: **PHP သို့မဟုတ် JavaScript** သုံးလို့ရတယ်။ Backend ကို backend ၂ ယောက်က ရေးမှာမို့ ဘာသုံးမလဲ သူတို့နဲ့ ညှိပြီး ရွေးမယ်
- **Frontend**: ကြိုက်တဲ့ဟာ ရွေးသုံးလို့ရတယ်
- **Tools**: ငါ့ global folder မှာ set up လုပ်ထားပြီးသား tools တွေကို သုံးလို့ရတယ်၊ လိုအပ်တဲ့ tools တွေကိုလည်း လိုသလို set up လုပ်ပြီး သုံးလို့ရတယ်

## ၄။ အကြံပြုခဲ့ပေမယ့် ငါ မရွေးရသေးတာ / အတည်မပြုရသေးတာ

ဒီအချက်တွေကို **ဆုံးဖြတ်ပြီးသားလို မယူပါနဲ့။** ဆွေးနွေးပြီးမှ ရွေးမယ်။

### Technology အကြံပြုချက်များ (မရွေးရသေး)

- Map: Leaflet.js + OpenStreetMap (အခမဲ့၊ API key မလို) ဒါမှမဟုတ် Mapbox GL
- Animation: GSAP + ScrollTrigger
- Database: MySQL (PHP ဆိုရင်) စတာတွေ
- Sound: Howler.js
- Visitor favorites သိမ်းဖို့ `localStorage`
- Local server: XAMPP သို့မဟုတ် Laragon
- Backend ကို JS နဲ့လုပ်ရင် Node.js စတာတွေ

### Scope ခွဲပုံ အဆိုပြုချက် (အတည်မပြုရသေး၊ ငါ မဖြေရသေး)

- **Phase 1 (မဖြစ်မနေ)**: map၊ နေရာစာရင်း (စမှာ ၁၅-၂၀ နေရာ)၊ category filter၊ cinematic landing နဲ့ detail page၊ login/register နဲ့ role ခွဲတာ၊ review/rating၊ save/visited၊ Nearby (GPS)၊ Route Planner
- **Phase 2 (အချိန်ရရင်)**: Add your business နဲ့ promotion post၊ Admin dashboard နဲ့ report စနစ်၊ Burmese/English ပြောင်းတာ၊ ထူးခြားချက် ၃ ခု
- ဒီခွဲပုံ မှန်မမှန် ငါ မဖြေရသေးဘူး၊ ပြန်မေးပါ။

### တခြား feature အကြံပြုချက်များ (ထည့်မထည့် မဆုံးဖြတ်ရသေး)

- Nearby (GPS နဲ့ အနားက နေရာရှာ)
- Route Planner (နေရာ ၃-၅ ခု ရွေးရင် အစီအစဉ်၊ အကွာအဝေး၊ ကြာချိန်)
- Budget Calculator (တစ်နေ့တာ ခရီးစရိတ်)
- Save / Favorites
- Transport Tips (ဘတ်စ်ကား၊ Circular Train၊ Taxi)
- နေရာတစ်ခုချင်းစီအတွက် cinematic detail page၊ မနက်/ညနေ/ည အချိန်ပြောင်းကြည့်တာ

### အဖွဲ့ တာဝန်ခွဲဝေမှု

Backend ၂ ယောက်နဲ့ frontend ငါ ဆိုတာ **အတည်ပြုပြီး** (အပိုင်း ၁.၁ ကြည့်ပါ)။ တခြား အခန်းကဏ္ဍတွေ (data စုသူ၊ designer၊ tester/writer စတာ) ဘယ်သူ ဘာလုပ်မလဲ ကတော့ **မသိရသေးဘူး**။

- ဒီအချက်တွေက ကျန်တာအားလုံးကို သက်ရောက်လို့ အရင်သိရမယ်

### ၂။ အဖွဲ့နဲ့ အချိန်
