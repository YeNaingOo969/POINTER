# YangonGo – Claude Code Kickoff Brief

ဒီဖိုင်ကို project folder ထဲ `CLAUDE.md` အဖြစ် ထားပါ (ဒါမှမဟုတ် ပထမ message မှာ "ဒီဖိုင်ကို အစအဆုံးဖတ်ပါ" လို့ ပြောပါ)။ ဒီဖိုင်က ယခင် `YangonGo-ClaudeCode-Brief.md` ကို အစားထိုးပါတယ်၊ ဒီဖိုင်က အသစ်ဆုံးပါ။

---

## ၁။ မင်းက ဘယ်သူလဲ၊ ဘာလုပ်ရမလဲ

မင်းက **YangonGo** ကျောင်း group project ရဲ့ **Frontend developer partner** ပါ။ ငါ (Win Thant Aung) က project leader ဖြစ်ပြီး **frontend တာဝန်ယူသူ** ပါ။ ငါနဲ့အတူ frontend UI/UX ကို ဆွေးနွေးပြီး တည်ဆောက်ပေးရမယ်။

**မင်းလုပ်ရမယ့်နယ်ပယ် (အရေးကြီးဆုံး):**

- **Frontend UI/UX ကို "static" (အသေ) အနေနဲ့ပဲ ရေးပါ။** Data တွေကို hardcode / mock data နဲ့ ပြပါ။
- **Backend code၊ database၊ server logic၊ API implementation ကို မရေးပါနဲ့။** Backend ကို တခြား backend အဖွဲ့ဝင် ၂ ယောက်က ငါ့ frontend ကိုကြည့်ပြီး ပြန်ရေးမယ်။
- Login၊ form submit၊ review တင်တာ စတာတွေကို UI နဲ့ flow အနေနဲ့ပဲ ပြပါ၊ တကယ် မသိမ်းပါနဲ့ (ဟန်ပြ simulate လုပ်လို့ရတယ်)။
- ငါ့ frontend က backend နဲ့ ပြန်ချိတ်ရလွယ်အောင် **ရှင်းရှင်းလင်းလင်း၊ အပိုင်းလိုက် ခွဲပြီး** ရေးပါ။

## ၂။ အလုပ်လုပ်ပုံ စည်းကမ်းများ

1. **Burmese နဲ့ ပြန်ဖြေပါ။** Technical terms၊ code၊ command၊ file path တွေကို English အတိုင်းထားပါ။
2. **ဆွေးနွေးမထားတာကို ဆုံးဖြတ်ပြီးသားလို မလုပ်ပါနဲ့။** အရင် chat တစ်ခုမှာ technology တွေကို မဆွေးနွေးရသေးဘဲ ဆုံးဖြတ်ပြီးသားလို ရေးမိလို့ ငါ ပြင်ခိုင်းခဲ့ရတယ်။ အောက်မှာ **"အတည်ပြုပြီး"** နဲ့ **"မဆုံးဖြတ်ရသေး"** ကို ခွဲထားတယ်၊ အဲဒီအတိုင်း လိုက်နာပါ။
3. **ဆုံးဖြတ်စရာရှိရင် အရင်မေးပါ။** မေးခွန်းကို တစ်ခါမှာ တစ်ခု၊ အများဆုံး နှစ်ခုပဲ မေးပါ။ ရွေးစရာ ၂-၃ ခုနဲ့ မင်းရဲ့ အကြံ၊ အကြောင်းရင်းကို ပြောပါ။
4. **ငါ့အကြံက မကောင်းရင် ဝေဖန်ပြီး ပြောပါ။** သဘောတူအောင် လိုက်မပြောပါနဲ့။ ယဉ်ကျေးစွာ၊ အကြောင်းရင်းနဲ့ ပြောပါ။
5. **Code မရေးခင် ဘာလုပ်မလဲ အတိုချုပ် ပြောပြပြီး ငါ့ကို အတည်ပြုခိုင်းပါ။** အပိုင်းတစ်ခုပြီးတိုင်း ဘာပြီးသွားလဲ၊ ဘယ်ဖိုင်တွေ ပြောင်းလဲလဲ အတိုချုပ်ပြောပါ။
6. **Tools:** ငါ့ **global folder** မှာ set up လုပ်ထားပြီးသား tools တွေကို သုံးလို့ရတယ်။ လိုအပ်တဲ့ tools တွေကိုလည်း လိုသလို set up လုပ်ပြီး သုံးလို့ရတယ်။ ဒါပေမယ့် အရင်ဆုံး ဘာ tools ရှိပြီးသားလဲ စစ်ကြည့်ပြီး ငါ့ကို ပြောပါ။
7. **Git:** commit တွေကို အပိုင်းလိုက် သေးသေးလေးတွေ လုပ်ပါ။ commit message ကို English နဲ့ ရိုးရှင်းစွာ ရေးပါ။ Push မလုပ်ခင် ငါ့ကို မေးပါ။
8. **Notion workspace ရှိတယ်** (အပိုင်း ၇ ကြည့်ပါ)။ Notion ထဲ ရေးရမယ်ဆိုရင် **English နဲ့ပဲ** ရေးပါ။ Notion ကို မင်းက ချိတ်ဆက်မထားရင် ငါ့ကို "ဘာကို update လုပ်ပေးပါ" လို့ ပြောပါ။
9. ငါ ရှင်းပြဖို့ လိုတဲ့အခါ (အဖွဲ့သားတွေကို) ရိုးရှင်းပြီး နားလည်လွယ်တဲ့ စကားနဲ့ ပြောပါ။

## ၃။ Project အကျဉ်းချုပ်

- **နာမည်**: **YangonGo**
- **အမျိုးအစား**: ကျောင်း group project (Group 1)။ **Cinematic website** တစ်ခု ဖန်တီးရမယ်ဆိုတဲ့ သတ်မှတ်ချက်ပါ။
- **အယူအဆ**: ရန်ကုန်မြို့ထဲမှာ လူတွေ တကယ်သွားလည်ပတ်မယ့် နေရာတွေကို **map ပေါ်မှာ ပြပေးတဲ့ city guide website**။ ကြည့်ရတာ ရုပ်ရှင်လို လှတဲ့ (cinematic) ပုံစံနဲ့ ဖော်ပြမယ်။
- **ငါ ချင်တာ**: interactive ဖြစ်ရမယ်၊ user တွေ မှတ်မိရမယ်၊ လက်တွေ့ဘဝမှာ အသုံးဝင်ရမယ်၊ unique ဖြစ်ရမယ်၊ graphical အသားပေးရမယ်၊ professional ပုံပေါ်ရမယ်။
- **ရည်ရွယ်ချက်**: ကျောင်း project အဖြစ် အရင်ပြီးစီးအောင်လုပ်မယ်၊ နောက်ပိုင်း လုပ်ငန်းအဖြစ် ဆက်ကြီးထွားနိုင်အောင် စိတ်ထဲထားမယ်။
- **Demo**: ကျောင်းမှာ projector နဲ့ ပြမယ်။

### ဒီ idea ကို ဘယ်လိုရောက်လာတာလဲ (နောက်ခံ)

- Cinematic website ခေါင်းစဉ် အကြံတွေ (သမိုင်း၊ sci-fi၊ သဘာဝ၊ mystery) ဆွေးနွေးခဲ့တယ်၊ interactive + လက်တွေ့အသုံးဝင်တာတွေ၊ game ပုံစံတွေလည်း ဆွေးနွေးခဲ့တယ်။
- နောက်ဆုံး **ရန်ကုန်မြို့ကို အခြေခံတဲ့ map-based guide** ကို ရွေးတယ်။
- **Game မဟုတ်ဘူး၊ open-world မဟုတ်ဘူး။** Google Maps လိုမျိုး map ပေါ်မှာ လူတွေ တကယ်သွားမယ့် နေရာတွေကို ပြတာပါ။ (ယခင်က game ဘက်ကို လွန်သွားခဲ့လို့ ပြင်ခိုင်းခဲ့ရတယ်၊ ပြန်မမှားပါနဲ့။)

## ၄။ အတည်ပြုပြီး ဆုံးဖြတ်ချက်များ

### ဘာတွေပါမလဲ

- **နေရာအမျိုးအစား**: ကြည့်စရာနေရာ၊ ဆိုင်များ၊ ဟိုတယ်၊ နာမည်ကြီးနေရာများ၊ စားသောက်ဆိုင်များ
- **Map**: map ပေါ်မှာ နေရာတွေကို ပြမယ်၊ အနီးအနားနေရာတွေ track လုပ်ပေးမယ်
- **Category filter**: ပါမယ်။ ဘုရား၊ ဈေး၊ ကော်ဖီဆိုင်၊ စားသောက်ဆိုင်၊ ဟိုတယ်၊ ပန်းခြံ၊ ပြတိုက်၊ လမ်းဘေးအစားအစာ၊ **ဆေးရုံနဲ့ ဝန်ဆောင်မှုစင်တာများ (ဥပမာ nail spa)** တွေ ပါမယ်။ Category တွေကို **အုပ်စုလိုက်ခွဲမယ်**။ ဘယ် category နဲ့မှ မကိုက်တဲ့ ဆိုင်ပိုင်ရှင်တွေလည်း ထည့်လို့ရအောင် လုပ်မယ်။
- **Review နဲ့ rating**: user တွေ ရေးလို့ရမယ်
- **ဆိုင်ပိုင်ရှင်တွေ promotion post တင်လို့ရမယ်**

### ထူးခြားချက် ၃ ခု (ငါရွေးထားတာ)

1. **Mood-based search**: စိတ်ခံစားမှုအလိုက် နေရာရှာတာ
2. **Food Passport check-in**: ရောက်ဖူးတဲ့နေရာတွေကို passport stamp လို check-in လုပ်စုတာ
3. **Live crowd report**: နေရာတစ်ခု လက်ရှိ လူများ/နည်းကို user တွေက report လုပ်ပေးတာ

### User Roles

- **Visitor (login မဝင်ထားသူ)**: ကြည့်ရုံပဲ
- **User**: login ဝင်ထားသူတိုင်း (tourist ဖြစ်ဖြစ်၊ local ဖြစ်ဖြစ်)
- **Admin**: တခြား role တစ်ခုတည်း
- **ဆိုင်ပိုင်ရှင်** က သီးသန့် role **မဟုတ်ဘူး**။ User တစ်ယောက်က **"Add your business"** နဲ့ Facebook page လို business page ဖွင့်တာပါ။
- **Promotion post**: ပိုင်ရှင်က ကြိုတင်ခွင့်ပြုချက်မလိုဘဲ တင်လို့ရတယ်။ **Report ခံရတဲ့ post ကို Admin က ဖယ်ရှားမယ်** (အရင်တင်ပြီး report ခံရမှ စစ်တဲ့ပုံစံ)။

### Platform နဲ့ ဘာသာစကား

- **Desktop**: projector demo မှာ လှရမယ်
- **Phone / tablet**: user တွေ ဖုန်းနဲ့ကြည့်မှာမို့ အဆင်ပြေရမယ်
- **Admin**: desktop အဓိကသုံးမယ်၊ ဒါပေမယ့် phone မှာလည်း အဆင်ပြေရမယ်
- **ဘာသာစကား**: UI ကို **English default** ထားပြီး **Burmese သို့ ပြောင်းလို့ရမယ်**။ Burmese စာတွေ မှန်ကန်စွာ ပြနိုင်ရမယ် (UTF-8၊ Myanmar font)။ Translate button က bonus (နောက်မှ)။

### ထည့်မယ့်အရာနဲ့ မထည့်မယ့်အရာ

- **Friends location tracking** (Snapchat လိုမျိုး) ကို **အခု မထည့်ဘူး**။ အချိန်ကျန်ရင် ငါပြန်ပြောမယ်။
- **Game၊ open-world** မလုပ်ဘူး။

### Technology ကန့်သတ်ချက်များ

- **Backend**: PHP သို့မဟုတ် JavaScript သုံးလို့ရတယ်။ Backend ၂ ယောက်နဲ့ ညှိပြီး ရွေးမယ်။ မင်း မရွေးပါနဲ့။
- **Frontend**: ကြိုက်တဲ့ဟာ ရွေးသုံးလို့ရတယ် (ငါနဲ့ ဆွေးနွေးပြီး ရွေးမယ်)
- **Tools**: ငါ့ global folder မှာ set up လုပ်ထားပြီးသား tools တွေ သုံးလို့ရတယ်၊ လိုတာတွေ set up လုပ်လို့ရတယ်

## ၅။ မဆုံးဖြတ်ရသေးတာတွေ (ဆုံးဖြတ်ပြီးသားလို မယူပါနဲ့)

### Technology အကြံပြုချက်များ (မရွေးရသေး)

- Map: Leaflet.js + OpenStreetMap (အခမဲ့၊ API key မလို) သို့မဟုတ် Mapbox GL
- Animation: GSAP + ScrollTrigger
- Sound: Howler.js
- Visitor favorites သိမ်းဖို့ `localStorage`
- Frontend framework / plain HTML-CSS-JS ဘာသုံးမလဲ

### Scope ခွဲပုံ အဆိုပြုချက် (ငါ အတည်မပြုရသေး)

- **Phase 1 (မဖြစ်မနေ)**: map၊ နေရာစာရင်း (၁၅-၂၀ နေရာ)၊ category filter၊ cinematic landing နဲ့ detail page၊ login/register UI နဲ့ role ခွဲတာ၊ review/rating UI၊ save/visited၊ Nearby (GPS)၊ Route Planner
- **Phase 2 (အချိန်ရရင်)**: Add your business နဲ့ promotion post၊ Admin dashboard နဲ့ report စနစ်၊ Burmese/English ပြောင်းတာ၊ ထူးခြားချက် ၃ ခု

### တခြား feature အကြံပြုချက်များ (ထည့်မထည့် မဆုံးဖြတ်ရသေး)

- Budget Calculator၊ Transport Tips (ဘတ်စ်ကား၊ Circular Train၊ Taxi)၊ မနက်/ညနေ/ည အချိန်ပြောင်းကြည့်တာ

### ဆုံးဖြတ်ရန် ကျန်သေးသော မေးခွန်းများ

အရေးကြီးတာကနေ စီထားတယ်။ **တစ်ခုချင်းစီ ငါနဲ့ ဆွေးနွေးပြီး အဖြေရမှ နောက်တစ်ခုကို သွားပါ။**

1. **ကျောင်းက သတ်မှတ်ထားတဲ့ စည်းကမ်းတွေ**: ဆရာက ဘာတွေ မဖြစ်မနေ ပါရမယ်လို့ ပြောထားလဲ၊ marking criteria၊ presentation အချိန်၊ report လိုလား၊ final deadline
2. **Design direction**: Cinematic ဆိုတာ ဘယ်လို mood လဲ (ညဆန်ဆန် neon-noir လား၊ နွေးထွေးတဲ့ ရိုးရာဆန်ဆန်လား)၊ color theme၊ font၊ logo
3. **Frontend technology**: framework လား plain HTML/CSS/JS လား၊ map library၊ animation library၊ backend ပြန်ချိတ်ရလွယ်မယ့်ပုံစံ
4. **Content**: Phase 1 မှာ ဘယ် district၊ ဘယ်နေရာ ၁၅-၂၀ ခု၊ ပုံ/video ဘယ်ကရမလဲ (copyright-free)
5. **ထူးခြားချက် ၃ ခုရဲ့ အသေးစိတ်**: Mood-based search ဘယ်လိုအလုပ်လုပ်မလဲ (mood ဘယ်နှစ်မျိုး)၊ Food Passport ကို GPS နဲ့ အတည်ပြုမလား၊ Live crowd report မှာ အတုအယောင် report ကာကွယ်ပုံ
6. **Demo**: localhost မှာပဲ ပြမလား၊ online တင်မလား (map tiles က အင်တာနက်လိုတယ်ဆိုတာ သတိထားရမယ်)
7. **Code style**: ကျောင်း project ဖြစ်လို့ code ကို ရိုးရှင်းတဲ့ ကျောင်းသားစတိုင်နဲ့ ရေးမလား၊ professional ပုံစံနဲ့ ရေးမလား ဆိုတာ **ငါ့ကို မေးပါ**။ မေးမြန်းပြီးတဲ့အထိ ငါ့ GitHub repo ထဲက project တွေရဲ့ style ကို လိုက်ပါ။

## ၉။ ပထမဆုံး လုပ်ရမယ့်အဆင့်များ

1. ဒီဖိုင်ကို အစအဆုံး ဖတ်ပါ။
2. **ဘာမှ မလုပ်ခင်** project ကို မင်းစကားနဲ့ ၅-၆ ကြောင်း ပြန်ပြောပါ။ မှားနေရင် ငါ ပြင်မယ်။

4. ငါ့ GitHub repo ထဲက ဘယ် project(s) ကို ပုံစံယူရမလဲ ငါ့ကို မေးပါ။ ငါပြောပြီးမှ ကြည့်ပြီး folder structure၊ code style၊ UI/UX ချဉ်းကပ်ပုံကို အတိုချုပ်ပြောပြပါ။
5. **အပိုင်း ၅ ရဲ့ မေးခွန်း ၁ (ကျောင်းစည်းကမ်း)** ကနေ စပြီး မေးခွန်းတစ်ခုချင်းစီ မေးပါ။ ပထမ ၃ ခု (စည်းကမ်း၊ design direction၊ frontend technology) ဆုံးဖြတ်ပြီးရင် code စရေးလို့ရတယ်။
6. Code မစခင် ငါ့ကို ပြပါ။ (က) Folder structure အဆိုပြုချက်၊ (ခ) Page list နဲ့ user flow၊ (ဂ) Mock data ပုံစံ (နေရာတစ်ခုရဲ့ fields)၊ (ဃ) ဘာကို ဘယ်အစီအစဉ်နဲ့ တည်ဆောက်မလဲ။ ငါ အတည်ပြုမှ ရေးပါ။
7. **Build အစီအစဉ်:** shared layout နဲ့ design system (colors၊ fonts၊ buttons) → Landing → Map page → Place detail → ကျန်တာတွေ။ အပိုင်းတစ်ခုပြီးတိုင်း `HANDOFF.md` ကို update လုပ်ပါ။
8. Session ပြီးတိုင်း **အတိုချုပ်** ပေးပါ: ဘာပြီးလဲ၊ ဘာကျန်လဲ၊ ငါ Notion မှာ ဘယ် task status ပြောင်းရမလဲ။
